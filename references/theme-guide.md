# 行业主题选择

8 套主题，切换只改 `<html>` 上的一个属性：

```html
<html lang="zh-CN" data-theme="medical">
```

暗色模式叠加 `data-dark="1"`：`<html data-theme="finance" data-dark="1">`

---

## 一、怎么选（按优先级）

1. **用户明说了行业** → 直接用对应主题，不问
2. **用户给了品牌色** → 选色系最接近的，然后在原型里改 `--c-brand*` 四个变量
3. **用户没说** → 按产品类型推断（下表），并在交付说明的「假设」里写一句"按 XX 行业选了 X 主题"
4. **实在判断不出来** → 默认 `saas`（靛蓝最中性）

**不要问"你要什么颜色"**——这是能用推断解决的问题，问了只会增加往返。

## 三、改品牌色的正确姿势

用户给了品牌色（比如 `#00875A`）时，**只改这四个变量，别动其他**：

```css
[data-theme="custom"] {
  --c-brand:       /* 填充色，白字压在上面必须 ≥4.5:1 */;
  --c-brand-hover: /* 比 brand 深一档 */;
  --c-brand-ink:   /* 白底上当文字用，必须 ≥4.5:1 */;
  --c-brand-soft:  /* 极浅底，用于选中态背景 */;
  --c-brand-line:  /* 浅描边 */;
  --c-focus:       /* rgba(brand, .32) 焦点环 */;
}
```

**搞不清就用 `--c-brand-ink` 和 `--c-brand` 设成同一个值**，再验证对比度：

```bash
node scripts/check-contrast.mjs "#00875A"
```

输出会告诉你这个色压在白底上、白字压在这个色上分别是多少，够不够 4.5。

### 为什么 `--c-brand` 和 `--c-brand-ink` 要分开

这是最容易被忽略的一处：

- `--c-brand` 用作**填充**（按钮底色），上面压白字 → 需要 **brand vs 白** ≥ 4.5
- `--c-brand-ink` 用作**文字**（链接、选中态文字），压在白底上 → 需要 **brand vs 白** ≥ 4.5

**这两个要求方向相反**：色越深，白字越好读，但作文字越难读。所以：

| 主题 | `--c-brand`（填充） | `--c-brand-ink`（文字） | 说明 |
|---|---|---|---|
| medical | `#0f766e` 白字 5.47 ✓ | `#0a8279` 白底 4.69 ✓ | 文字版略亮一档 |
| ecommerce | `#be123c` 白字 6.29 ✓ | `#e11d48` 白底 4.70 ✓ | 文字版亮两档 |

医疗那个原始的品牌青 `#0d9488` 白底只有 3.74 —— **不能直接当文字用**，必须换成深一档的 `#0a8279`。这是我在做主题时实测发现的，不分开设就会有一批文字读不清。

## 四、语义色不跟着主题变

`--c-success / --c-warning / --c-danger / --c-info` 是**固定值**，所有主题共用。

原因：状态色是**约定**，不是装饰。如果 `medical` 主题的成功色是青绿、`education` 的成功色是橙，用户在两个系统间切换就会误判。红=错误、绿=成功这条不能为了配色和谐而让步。

唯一的例外是暗色模式下这四组色需要提亮，已经在 `theme.css` 的 `[data-dark="1"]` 里处理。

## 六、什么时候该用暗色

默认**不用**。原因：

- 原型的目的是给非技术同事看，浅色在投影仪和微信截图里更稳
- 暗色需要额外验证对比度，容易出问题
- 真有暗色需求（监控大屏、开发者工具）再加 `data-dark="1"`

生成时如果判断产品有"大屏监控"属性，可以主动做一版暗色截图作为补充，但主版本保持浅色。
